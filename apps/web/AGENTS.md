# React UI/UX·데이터 기반 화면 배치 및 접근성

**현행 웹 개발:** 이서연 `lhh42001`([#357](https://github.com/ot4562-glitch/HUFS-One-AI/issues/357))이 기존 사이트의 **UI/UX 디자인·반응형 컴포넌트·실제 기능 API/데이터 배치**를 주도한다. 김채윤 `qamarrchae`([#358](https://github.com/ot4562-glitch/HUFS-One-AI/issues/358))의 실사용 포스터·공고·이미지/본문·권리 정본을 디자인에 활용한다. 박준영은 AI 제품 기술 QA, 김채윤은 데이터를 직접 넣어 전체 흐름을 가볍게 시연하고 관찰 사항을 이슈에 공유한다. 심민성 `ot4562-glitch`이 모든 단계의 디자인·코드·통합을 검수한다.

**추가 기능 협업:** 새 `[추가 기능]` 이슈는 최초 심민성이 구조와 Core·Contracts/API 인터페이스를 마련한 뒤 박준영/이의상 중 **한 명에게 본기능 개발을 인계**한다. 이서연은 기능 이슈의 실제 API/화면 요구와 데이터 인수에 맞춰 웹 라우트·디자인을 구성한다. [루트 AGENTS](../../AGENTS.md) · [팀 역할](../../docs/WORKSTREAMS.md).

- 넓은 화면에는 검증된 GNB/LNB, 모바일에는 현재 프로젝트의 하단 탐색을 재사용한다. 원본 HUFSAbility의 미지원 메뉴는 구현된 실제 기능과 구분해 표시한다.
- 합성 S01–S05/EMPTY·ADMIN/REVIEWER와 실제 BETA 계정의 학생 원본·권한을 분리한다. 현재 actor/동의·SourceRevision/권리·갱신 시점을 UI에서 정확하게 반영한다.
- 401/403/409/429/503, 브라우저 뒤로가기·다중탭·권한/자료 철회·늦은 응답에서 사용자 간 상태·캐시·이미지·비밀이 혼합되지 않도록 코딩한다.
- 키보드/Disclosure Escape, 포커스/heading, 320–1440px 반응형, 스크린리더/alt/읽기 순서를 고려한 컴포넌트를 구현한다. 코딩/자동 CI와 실제 사람·기기 인수 결과를 구분한다.
- 김채윤이 제공한 이미지·원문은 게시 이용권 확인 범위 안에서 표시하고 합성 예시는 시연용으로 명시한다. 서버 검색 범위·학사/AI 결과의 불확실성/근거를 실제 값대로 표시한다.
- 변경 화면의 API/계약·PR SHA와 현재 HEAD 테스트 증거를 공유한다. AI QA에서 접수된 화면 개선 사항은 총괄이 원인/작업 범위를 정리하여 구현 담당에게 전달한다.
