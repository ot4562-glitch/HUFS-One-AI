# HUFS One AI — 현재 프로젝트 승인과 실행 상태

## 승인 완료

프로젝트 소유자 심민성은 저장소 문서에 기재된 **개인정보·자료·정보 이용, 기관/출처, 공유·게시·보관, 클라우드/모델 전송, 운영 및 출시의 모든 승인을 받은 상태**라고 명시했습니다. 현재 프로젝트 승인 상태는 **`OWNER_CONFIRMED_APPROVED`**입니다. 승인 미취득을 이유로 동일한 허가를 다시 요구하거나 모든 기능을 일괄 비활성화하지 않습니다.

이 기록의 근거는 **소유자의 승인 완료 확인**입니다. 읽지 않은 계약서, 기관 담당자의 독립 서명, 미실행 시험·배포·성능 수치를 새로 확인했다고 주장하지 않습니다.

## 공개 웹 수집 범위 확대 — 2026-11-10 제안

프로젝트 소유자는 **일반인 또는 일반 학생이 정상적인 웹 사용만으로 볼 수 있는 공식 학교 정보의 광범위한 발견·구조화**를 제품 목표로 정한다. 공개 페이지마다 개별 URL 권리 영수증을 요구하는 방식은 범용 **발견 단계**의 기본 조건으로 사용하지 않는다. 공개 URL의 발견, 자동 HTTP/브라우저 취득, 원문 보존, 대외 재게시, 외부 AI 전송은 서로 다른 작업과 허용 범위이다.

`robots.txt`는 접근 허가 자체가 아니라 크롤러 규칙이다. `Disallow`가 있는 자료도 데이터 수집 **후보에서 제거하지 않고**, 공식 데이터 제공·사이트별 운영자 검토를 거친 공개 페이지 취득·정당한 사용자 저장본 등의 수집 경로를 관리한다. 그 자체를 근거로 봇 방어·로그인 장벽을 무력화하는 자동화를 허용하지 않는다. 일반 학생용 자료는 승인된 접근권·계정 범위에서만, 개인별 성적·학적 등은 별도 비공개 동의/목적별 경로로만 처리한다.

이 변경의 전체 기준과 **아직 구현되지 않은 코드 변경**은 [공개 웹 정보 수집 정책](PUBLIC_WEB_INGESTION_POLICY.md)을 따른다. 본 문서는 제3자 기관별 재게시·개인정보 처리 권리까지 포괄적으로 입증한 것으로 해석하지 않는다.

## 승인이 허용하는 구현

승인된 실제 정보는 인증된 서비스 경로에서 처리할 수 있습니다. 운영 모드는 `runtime:'production'`으로 명시하고 실제 OIDC·학교메일·DB·공급자 설정을 연결합니다. `APP_ENV=production`이라는 이유만으로 구성된 운영 앱 전체를 거부하지 않습니다. 모델/운영을 켜는 기능은 서버 측 설정으로 제어하며 브라우저의 임의 필드나 전역 허용 플래그를 인증 주체로 사용하지 않습니다.

## 기술적 안전장치는 유지

인증·사용자별 소유권, ADMIN/BETA/REVIEWER 역할, CSRF, 세션 만료, RLS/최소권한, 실제 삭제·철회 상태, 비밀키/토큰 보호와 잘못된 입력 거부는 승인 대기가 아니라 서비스의 정상 동작 조건입니다. 프로젝트 전체 승인과 익명 관리자 접근·타인 신원 가장·비밀키 공개는 다릅니다.

## 상태를 세 가지로 구분

| 항목 | 현재 의미 |
| --- | --- |
| 승인 | `OWNER_CONFIRMED_APPROVED`; 승인 부족에 의한 일괄 차단 없음 |
| 구성 | 실제 주소·키·SQL role·OIDC/메일·가격·공급자 설정이 빠졌으면 `CONFIGURATION_REQUIRED` |
| 실행/품질 | 실제 결과에 따라 `PASS`, `FAIL`, `NOT_RUN`, `NOT_MEASURED`; 승인 완료만으로 성공 처리하지 않음 |

실제 NCP VM/운영 SQL migration/배포·외부 공급자 호출은 대상과 자격증명이 구성된 환경에서 실행합니다. 개발용 합성 서버를 production으로 속여 운영하지 않습니다. 실제 원본은 필요한 서비스에서 처리하며 자격증명이나 무관한 개인정보를 테스트 로그·브라우저 번들에 넣지 않습니다.
