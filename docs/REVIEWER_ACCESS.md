# HUFS One AI — 제한된 학교 심사자 합성 접근 계약

**현재 상태:** 서버·React의 합성 REVIEWER 초대/권한/격리/세션 관련 코드가 있으며 **실 Google·외대 메일·실 운영 DB/도메인·실제 초대 발행/전달은 수락 전**입니다. 운영 공개·심사자 개인 데이터 입력은 금지. [#252 B01](https://github.com/minseong-hufs/HUFS-One-AI/issues/252) · [#253 API](https://github.com/minseong-hufs/HUFS-One-AI/issues/253).

## 접근 원칙

REVIEWER는 일반 학생/ADMIN과 다른 role이다. 로그인한 reviewer가 학생 5명의 **합성 데이터만** 살펴보는 제한된 시연 목적이며 실제 원본 4명·실개인 계정·유료 AI·공식 학교 시스템에 접근할 권한은 없다. 학생/관리자 데이터가 같은 브라우저/세션에 섞이지 않도록 하며, 미지원 메뉴는 미지원 표시로 둔다.

## 초대장·등록

- 심사자 이메일을 미리 모르는 경우에도 사용할 수 있는 별도 **A4 공용 초대 템플릿**(비활성 예시)만 저장소에 둘 수 있다. **활성 초대 URL/OTP/토큰/서명키는 Git·PDF·이슈·CI에 두지 않는다**.
- 충분한 엔트로피(32바이트 CSPRNG)·서버 해시/1회 교환·fragment 즉시 제거, 초대 범위/시작·만료/철회, 등록 20명 기본 한도, actor/IP/초대 rate limit·분산 저장, 현재 구글 `sub`와 검증된 학교메일 소유를 현재 session에 결속.
- UI는 expired/revoked/used, CSRF·401/403/409/429/503·새 탭/이전 캐시·StrictMode/늦은 응답을 안전하게 처리한다. 권한 만료 뒤 개인/합성 비공개 자료를 다시 노출하지 않는다.
- 외부 링크가 있는 공개/보호 페이지, 로그아웃·초대 해제·브라우저 뒤로 가기·복원·재로그인을 실제 인증 보안 경계에서 검사.

## 시연과 인수

보여 줄 수 있는 것은 5가상 대상의 맞춤 공고/공지·일정·학업 UNKNOWN·경험/보관함/계획/가상 동아리 등 **구현된 합성 기능**이다. 실제 제출·외부 메시지·모델 유료 호출은 꺼둔다.

- [ ] 운영 Google OIDC/학교 메일 인증·PostgreSQL role/RLS·초대/철회/분산 quota·직접 URL/캐시/세션 부정시험.
- [ ] 360px·키보드/스크린리더·2탭/실기기·role별 미지원 배지와 focus·권한 변화 독립 인수.
- [ ] 합성 전용 0 외부원본/0 유료 AI 호출·지원 액션 비활성 확인.
- [ ] 실제 초대 문서·인쇄/발송과 기관 승인/자료 권리를 별도 사람이 검토.
