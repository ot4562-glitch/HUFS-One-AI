## 0. 조사 대상과 신뢰도

- 관찰 대상: 2026-11-02 본인 계정으로 접근 가능한 HUFSAbility 학생용 서비스 화면. 원본 웹 페이지 수집본은 로컬 비공개 공간에 보관하며 이 문서와 함께 전송하지 않음.
- 새 조사 결과: 발견 메뉴 77개 중 화면 76개 저장, 1개 리다이렉트 오류. 서로 다른 페이지 경로 76개, PNG 76개/서로 다른 이미지 해시 76개, HTML 76개, 저장 파일 누락 0. 대표 화면의 스타일/DOM 메타데이터도 76개 존재.
- 추가 과거 보관본 202개 중 대표 구조 33건을 별도 검토한 이력이 있으나, 이 문서는 **새 76개 화면 관찰을 정본으로 삼는다**. 서로 다른 URL이 실제로 다른 화면임은 확인했고, 모든 화면의 마우스/키보드 UX를 완주한 것은 아니다.
- 화면 수집 환경: 브라우저 viewport **1440×900 CSS px**, 실제 전체 페이지 PNG 폭 **1425px**. 이 차이는 스크롤바 등의 가용 폭 영향으로 보인다. 아래 좌표는 **PNG 왼쪽 위 (x=0,y=0)** 기준이고 **px** 단위. 다른 브라우저, 확대 배율, 반응형 폭에서 값이 다를 수 있다.
- 증거 등급: **[M]** 수집 시 실제 CSS/요소 bounding rectangle 수치, **[P]** PNG의 픽셀 위치·색상 측정, **[V]** 렌더된 화면을 보고 식별한 모양, **[D]** 안전하게 요약한 DOM 요소 개수·메뉴 계층, **[H]** 문구·모양에서 합리적으로 추정한 기능, **[U]** 실행/전환을 확인하지 못함.
- **정확도의 경계:** 검색창, 상태 배지, 탭, 파일 입력 등은 화면에 보인 상태만 설명한다. 클릭 뒤의 서버 동작, 검색결과의 정확성, 신청·저장·삭제 실제 실행, 접근성, 모바일 동작, 기관 승인 여부는 이 수집으로 확인되지 않았다.

- 내부 본문의 실제 CSS 최대폭 1010px은 **여러 표와 설명 영역의 관측 값**이다. 모든 자식 요소의 폭이 1010이라는 뜻은 아니다. 장학/상담 일부 표는 1080~1360, 취업통계 일부 표는 **2260~6340px**로 측정되어 화면 폭을 넘는다.
- 배너 높이는 이미지 픽셀 분류로 y≈100~241 범위를 확인했다. 랜딩 화면이나 외부 모듈 iframe에는 이 구조가 적용되지 않을 수 있다.

**정책상 구분:** 이 항목의 RGB는 **수집 시 화면 픽셀의 관찰값**이다. 학교 공식 브랜드 팔레트의 승인/재배포 근거가 아니다. HUFS One AI의 공식 컬러 계약은 별도 Architecture.md A11.2에 있고 색상 표기 또한 다를 수 있다. 따라서 여기의 수치는 **존재하는 요소의 시각적 특징을 이해하기 위한 값**이다. 로고·학교 캐릭터·그래픽·폰트 파일은 이 문서에 포함하지 않는다.

- **목록 하단:** 왼쪽 건수, 오른쪽 페이지 지표, 중앙 숫자/화살표 페이지네이션. 결과 0건일 때 중앙 느낌표+빈 상태.
- **UI 목적:** 학생이 공지·질의·자료를 날짜/제목 중심으로 찾고 상세 열람/신규 등록에 들어가도록 하는 구조. 글 읽기/작성·답변 제출은 이번 조사에서 실행하지 않음.

### 5.3 강의·수강·학업형: 교과(이수과목/수강과목/성적)

- **모양:** 좌측 메뉴에서 교과(이수/수강/성적) 그룹이 펼쳐지고 현재 항목을 청록 불릿으로 표시. 상단 둥근 검색 패널 안에 연도/학기/구분/검색어 드롭다운/입력칸, 오른쪽 검색·원형 초기화가 들어간다. [V]
- **표:** x≈343부터 너비≈1010. 헤더 '번호/수강학기/구분/과목명/학점/담당 교수님' 등을 사용하고, 학년·학기·과목이 여러 행으로 나온다. 회색 얇은 격자와 40~55px 정도의 행 높이.
- **개별 역량 점수 화면:** 좁은 기본 테이블과 달리 상단 개인별 **역량 요약 표**, 중간 조회 조건, 아래 **교과 역량/비교과 역량/외부비교과 역량** 선택 탭, 긴 교과별 점수표가 세로로 이어진다. 각 학생의 항목값·실제 점수는 이 문서에 복제하지 않음.

### 5.4 비교과 공고: 썸네일 + 역량 칩 + 지원 상태 패널

- **검색:** 목록 맨 위 여러 줄의 필터 상자. 운영 부서, 개최 연도/학기, 상태 또는 분류, 캠퍼스, 검색어 등 다수 옵션이 분산 배치됨. 검색 버튼 옆에 세 줄 슬라이더처럼 생긴 **상세 조건** 제어가 있는 화면도 보임.
- **공고 카드:** 검색 아래 최신/모집 등 상태를 고르는 텍스트 탭이 있고, 각 항목이 **세로로 높이가 큰 가로형 카드/목록행**이 된다. 왼쪽은 작은 세로 포스터(없을 때는 회색 이미지 대체), 가운데에는 조직명(작은 파란 글), 두꺼운 제목, 2~4개의 **남색/청록/주황/초록 역량 칩**, 설명·기간·대상 글이 층층이 놓인다.
- **오른쪽 컬럼:** 다른 카드 데이터와 달리 **밝은 푸른 회색의 세로 배경**이 한 줄 내내 지속되고, 짙은 남색의 '신청하기/모집중/마감' 형태 작은 상태 버튼 또는 배지와 **신청자/모집정원/대기자/포인트** 표시가 세로로 정렬된다. [V]
- **치수:** 목록의 실제 첫 표 요소 경계는 x=343, w=1010, 첫 화면에서는 y≈554부터 장문 영역. 포스터·제목·상태열의 정확한 픽셀 폭은 고정 실측값이 없어 *일반 본문 1010px의 안쪽에서 약 15~25% / 55~65% / 15~20%를 차지하는 것으로 보임* [V, 근사]; 구현 규격으로 취급하지 말 것.
- **장학 공고:** 같은 '왼쪽 썸네일/중앙 제목/오른쪽 상태' 패턴에 연도·학기, 장학구분 등 필터가 추가되는 변형.
- **목적:** 하나의 행에서 내용·지원기간·역량·신청 가능성을 빠르게 훑어보게 한다. 원문 상세/실제 신청 버튼의 최종 동작은 검증되지 않았다.

### 5.5 일반 채용·아르바이트: 밀도 높은 정보 테이블

- **모양:** 일반 채용 페이지는 비교과 프로그램 이미지 카드 대신 **가로표**를 주로 사용. 상단 1~3줄 필터에는 직종 콤보박스, 근무지역 체크박스 **다수**, 키워드 입력과 리셋/검색 버튼이 있다.
- **표 열:** 번호·회사명·채용제목(파란 링크)·근무형태·급여·지역·마감일과 같은 정보를 한 행에 배치. 제목이 긴 경우 줄바꿈하므로 행 높이는 일정하지 않을 수 있다.
- **행동:** 공고 상세 링크를 통해 더 읽을 수 있을 것으로 보이지만 전환/외부 링크 처리는 미확인. 페이지 하단 중앙의 1~10 숫자/양끝 화살표가 대량 목록을 탐색하게 한다.

### 5.6 학습공동체: 학기+유형 필터와 표

- **모양:** 좌측 '학습공동체'가 펼쳐지면서 '모집공고/활동관리/우수/전체공지/전체Q&A'가 들여쓰기. 검색에는 운영년도, 운영학기, 학습공동체 유형, 제목/내용 키워드가 보인다.

### 5.7 비교과 관심키워드: 다열 태그 선택기

- **모양:** 안내박스 아래에 카테고리 제목(직무, 기업·직종, 학습, 취·창업, 심리, 현장참여 등). 각 카테고리는 **연회색 사각 패널** 안에 얇은 회색 테두리의 **둥근 흰 캡슐 칩**이 보통 한 줄 5개씩 격자 형태로 놓인다. 내용 길이에 따라 각 칩은 1행 중심 정렬.

- **선택 상태:** 사용자가 키워드를 누르면 선택/해제할 것으로 안내문에 쓰여 있지만 **실제로 클릭하여 시각 상태 변화를 기록하지 않았다**. 따라서 기본 미선택(흰 배경·회색 외곽선) 상태만 확인됨.
- **목적:** 비교과 공고 추천/개인 관심사 분류용 선호정보 선택.

### 5.8 진로방향설정: 그림 아이콘 대형 선택 타일→직무 그리드

- **모양:** 상단 노란 느낌표 안내. 그 아래 **STEP 01** 청록 소형 캡슐과 '졸업 후 진로' 제목. 4개 큰 정사각에 가까운 타일이 한 줄에 배열되며, 각 타일은 상단 선 아이콘(서류가방, 메달, 전구, 학사모), 중앙 굵은 이름, 하단 짧은 설명. **첫 선택 타일이 넓은 주황 배경+흰 글씨**, 나머지는 흰 바탕·회색 선·회색 글씨.
- **STEP 02:** 직종/직무 옵션이 5열 내외의 짧은 **사각 매트릭스**. 선택된 항목은 청록 바탕, 나머지는 흰 배경. 아래쪽 우측에 '저장' 짙은 남색 버튼.
- **치수:** 본문 x≈343~1353, 1단계 선택 타일 각각 대략 240×225px 주변(화면에 따른 근사). 2단계 항목은 약 200×50px 내외로 관찰됨.
- **목적:** 진로 방향과 직종/직무 분류를 단계적으로 설정하는 양식. 저장 버튼 실행/유효성 검사는 하지 않음.

### 5.9 개인 진로/포트폴리오: 개인정보 표 + 분류 선택 + 공백 처리

- **진로 로드맵:** 상단에 학생별 표 형태 요약, 학년별 목표/달성/달성률 격자, 아래에는 **START → FINISH** 형태의 진행도 시각화 구역이 있다. 계획 이력이 없다면 비어 있는 플로우를 볼 수 있다.
- **이력서:** 열 구조가 있는 빈 상태 테이블 위·아래로 제목/등록일/공개/관리 등을 보고, 오른쪽 아래 남색 '등록' 버튼이 있음.
- **MY커리어:** 왼쪽 프로필 사진 영역, 오른쪽 이름/학과/연락 분야 등이 **라벨-값 쌍의 표**로 표시됨. 그 아래 3열 정도의 섹션 선택 바(이력서/자기소개서/교과성적/비교과 내역 등)와 빈 경우 느낌표, 오른쪽 아래 '선택/저장' 동작이 있다. **값을 문서화하지 않는다.**
- **취업도서관리:** 도서 대출·이력 확인용 게시판형 검색/목록 구조.
- **목적:** 개인 진로 경로, 이력서·자기소개서·경력의 구조적 관리. 등록/공개 여부 실제 권한과 서버 실행은 미검증.

### 5.10 상담 신청: 이미지가 있는 여러 개의 서비스 설명 카드

- **모양:** 본문 상단에 짧은 노란 아이콘 안내 1행. 다음으로 **상담 서비스 카드가 세로로 약 8개** 쌓임. 각 카드는 흰 바탕+얇은 테두리, **왼쪽 세로 사진(폭 약 100px 근처)**, 가운데 굵고 큰 상담명과 1~2줄 안내, 오른쪽 상단 **짙은 남색 상담신청 버튼**. 우측 하단에 기관 상징 이미지가 표시되는 경우도 있음.
- **종류:** 교수/지도, 진로취업, 심리, 학습, 전공설계, 영어 글쓰기 튜터링, 외국인 유학생, SG Unit 등. 국제학생 관련 카드의 버튼은 영어/중국어로 나뉘기도 함.
- **치수:** 본문 x≈343~1353, 각 카드 높이 보통 **100~140px 정도로 관찰**. 사진이 왼쪽을 차지하고 가운데 텍스트 영역이 가장 넓으며 오른쪽 버튼 폭은 약 100px 주변.
- **목적:** 지원 서비스 목록에서 적합한 상담을 선택해 신청 진입. 달력/상담사 선택/실제 예약은 여기서 누르지 않았으므로 기록하지 않음.

### 5.11 역량진단 결과: 차트+표+상담 연결

- **모양:** 상단 설명/주의 박스. 아래 큰 그래프 패널에 **6개의 보라색 세로 막대**가 있고 왼쪽 0~5 범위 눈금, 하단 역량 이름, 막대 내부 흰 수치가 있다. 그래프 오른쪽 위에 **청록 선택/회색 비선택**의 막대·선 그래프 변환 버튼.
- **아래:** 연도별 6개 역량 점수 비교 표, '보기' 회색 소형 버튼, 상담 기관/영역/연락/상담분야 안내의 다열 표가 이어진다.
- **목적:** 학생별 핵심역량 평가를 한눈에 비교하고 필요한 상담 분야로 연결. 실제 점수·학생 식별값은 이 문서에서 배제.

### 5.12 오픈배지: 단계 흐름을 설명하는 긴 안내

- **모양:** 별도의 오픈배지 분류 배너. 소개 페이지 상단에 **푸른 외곽선의 큰 원형 아이콘 4개가 가로 배열**되고, 아래 타원형 청록 테두리 설명줄과 '학습/활동 이력→디지털 인증→성과 증명'의 원형 도식이 있다. 그 아래 작은 설명 문단, 사각 기능 안내 칩, 표, 굵은 소제목이 긴 스크롤로 이어짐.
- **My 오픈배지:** 위쪽 비교과/실적 분류별 **가로 요약 카드**와 비어 있을 때 **물음표가 있는 원형 보관함 카드** 여러 개를 5열가량 배치한다. 일부 카드에 '상세보기' 유사 버튼이 보이며 하단에 안내문과 추가 이동 버튼이 있다.
- **목적:** 학생 활동 이력/자격의 디지털 배지 체계를 설명하고 개인 배지를 확인하는 UI.

### 5.13 취업통계: 조합형 필터 + 넓은 다단 헤더 표

- **모양:** 왼쪽 메뉴에 산업분류·기업유형·근무지역·초임급여·학과계열·학과전공별 등의 메뉴. 본문 상단 필터의 연도/소계열/학과, 조직 검색, 키워드와 회색 리셋·남색 검색이 한 줄에 있다.
- **표:** x≈343부터 시작하며 **2~3행짜리 그룹 헤더**(대분류, 계, 남/여 등)가 있다. 실제 첫 표의 너비가 화면마다 **2260, 2740, 5140, 5680, 최대 6340px**로 측정되기도 했다. 사용자에게 전부 보이는 폭이 아니라 **DOM 내부 표 너비**이다.
- **목적:** 조건에 따른 취업·분포 통계 조회. 현재 캡처에서 많은 표는 **헤더만 보이고 행 데이터가 비어 있음**. 빈 결과와 조회 실행 전 초기 상태를 혼동하지 말 것.
- **사용성 주의:** 긴 너비는 PC에서도 가로 스크롤 가능성을 시사하지만, 실제 스크롤 동작/고정열 여부는 미검증.

## 6. 관측된 UX 흐름과 검증되지 않은 경계

1. **대분류 전환:** 헤더에서 상위 메뉴를 선택하면 해당 메뉴 글씨만 주황색 활성화, 배너 제목·일러스트·LNB 그룹·본문이 함께 바뀌는 모습이 여러 화면에서 일관됨 [V]. 전환 중 애니메이션과 클릭 트리거는 미검증.
2. **중·소분류 전환:** 좌측 LNB에서 2단계 그룹 아래 세부 항목이 연회색으로 펼쳐지고 활성 항목만 청록 표시 [D/V].
3. **검색 패턴:** 필터 설정 → 남색 검색 → 표/목록 업데이트로 보이는 전형적인 조회 설계 [H]. 실제 클릭 후 응답, 정렬, 유효성은 측정하지 않음.
4. **목록→상세:** 링크 제목이 파란 밑줄로 표시되고 외부/내부 상세로 연결될 것으로 보임 [H]. 이번 새 수집에서는 공고 상세 자동 방문 **0건**이며, 리스트 화면만으로 세부 상세의 규격을 단정하지 않음.
5. **프로그램 선택:** 관심키워드 캡슐, 진로 타일, 분야 매트릭스, 탭 등의 선택 컨트롤이 있으며, 선택 상태 스타일은 진로/일부 탭에서 관찰됨 [V]. 전부 선택해서 반영한 결과는 미검증.
6. **폼 상태:** 검색/조회 폼과 실제 등록·저장·신청 폼은 겉보기만 유사한 경우가 있다. 행·폼 태그 개수가 서버 변경 권한을 뜻하지 않음. 신청/저장/삭제·실제 예약은 실행하지 않았다.
7. **데이터 없음:** 중앙 노란 느낌표와 메시지, 0건, 비활성화된 버튼 등이 함께 나타나는 페이지가 있다. 무조건 오류/데이터 없음으로 고정 처리해서는 안 됨.
8. **언어/국제화:** 상단 구글형 언어 드롭다운, 상담의 영/중 메뉴/신청 버튼을 확인. 실제 전 페이지 번역 품질과 locale 상태보존은 미검증.
9. **반응형:** 이번 원본 수집은 1440px PC 화면만 검증. 320/360/390/768px의 원본 동작과 모바일 메뉴·레이아웃 배치는 **미확인**이다.
10. **접근성:** 마우스/키보드 초점, aria 속성의 정확성, 색상 대비, 읽기 순서, 스크린리더, 확대에서의 상호작용은 확인되지 않았다. 원본의 보이는 형태만 기술했다.

## 8. 화면 유형별 추가 요소: 검토자가 특히 놓치기 쉬운 차이

- **통합상담**은 검색 후 표만 보여주는 페이지가 아니라 사진이 있는 여러 서비스 설명 카드 목록이다. 신청 버튼은 서비스별 카드의 **오른쪽 끝**에 있다.
- **비교과프로그램/장학 신청**은 단순 행 테이블이 아니라 포스터/설명/역량칩과 정원/상태가 있는 **3구획 공고형 리스트**다.
- **교과목·일반채용·커뮤니티**는 높은 정보 밀도의 전형적인 **표+페이징** 화면이다. 제목 링크의 언더라인·전체 건수·선택 페이지 테두리가 눈에 띈다.
- **핵심역량 결과**는 학교 안내형 표와 달리 **보라색 6축 막대그래프**를 포함한다. 차트 내부의 점수는 개인값이므로 문서화하지 않았다.
- **개인 진로정보/포트폴리오**에는 학생별 식별·민감 데이터가 표시될 수 있으므로 UI 구성만 인벤토리에 남겼다.
- **관심키워드**는 그리드 테이블로 오해하기 쉽지만 카테고리별 **캡슐 선택칩 묶음**이다.
- **진로방향설정**은 네 개 큰 그림 타일과 직종 매트릭스가 단계적으로 이어진다. 상세 제어의 선택 색이 주황과 청록으로 구분된다.
- **오픈배지**는 상태 배지 몇 개가 아니라 원형 일러스트/성과 흐름이 있는 **긴 안내 문서형 화면**과 개인 배지 카드 화면으로 나뉜다.
- **통계**는 일반 표 너비를 크게 초과하는 다중 열 수를 갖고 있어, x≈343 본문 폭 1010px이라는 기본 레이아웃만으로 설명할 수 없다.
- **일부 메뉴는 비어 있음:** 빈 상태, 기간/권한/사용자별 자료 없음, 수집 당시 아직 조회 전 상태는 서로 다르다. 사용자에게 보이지 않은 데이터나 기능을 임의로 채워 문서에 기록하면 안 된다.

#### 기존 HUFSAbility 참고 메뉴

- 참고 공개 기능 5분류: **역량관리 4, 교과/비교과 5, 채용 6, 경력개발 4, 통합상담 5 = 24개**.
- 공개 안내 4영역: 교내비교과·장학공지·공지사항·채용정보. 공식 홈페이지 새 창 링크로만 안내한다.
- 공개 5분류 24기능·공개 4영역 manifest는 `/menu` 전체 메뉴 페이지에서 그대로 보여 준다(텍스트와 `미지원`, 공개 4영역은 공식 첫 화면 새 창 링크).
- 학교 학생 계정에서 관찰된 **11개 정보 영역**은 넓은 화면 GNB와 각 대분류 LNB의 원래 메뉴 이름으로 쓴다. 76개 원래 화면을 구현하거나 복제한 것은 아니며, 학교 교표·로고·건물 사진·학번/비밀번호 로그인 화면은 쓰지 않는다.

#### 현재 메뉴 구현·추가기능 협업 상태 (2026-11-09)

신규 `[추가 기능]` 이슈는 **심민성이 최초 assignee**로 구조/일반 코드를 가능한 범위까지 구현하며, 추천/랭킹·규칙/코드 기반 AI·LLM/OCR 등은 **박준영 또는 이의상에게 실제 구현을 인계**한다. [#339–#352](https://github.com/ot4562-glitch/HUFS-One-AI/issues/339) 중 13개 기능의 AI 개발 담당은 박준영 6개·이의상 7개이고, **김채윤은 모두 데이터 공동 assignee**다. 실제 데이터 요청은 [#360](https://github.com/ot4562-glitch/HUFS-One-AI/issues/360)이며, 새 자료 요청은 별도 `[데이터 요청]` 이슈로 만든다.

**이서연**([#357](https://github.com/ot4562-glitch/HUFS-One-AI/issues/357))은 기존 웹사이트에 기능을 실제 배치하고 김채윤이 준비한 허가된 포스터·공고를 화면 디자인에 활용한다. **박준영**([#356](https://github.com/ot4562-glitch/HUFS-One-AI/issues/356))은 AI 제품 QA, **이의상**([#355](https://github.com/ot4562-glitch/HUFS-One-AI/issues/355))은 AI 교차 검증, **김채윤**([#358](https://github.com/ot4562-glitch/HUFS-One-AI/issues/358))은 가벼운 사용자 시연, **심민성**([#359](https://github.com/ot4562-glitch/HUFS-One-AI/issues/359))은 전체 코드/품질/통합 검수를 수행한다.

**고정 역할 #355–#359에는 더 이상 수정·댓글·담당 변경 등 어떤 쓰기도 수행하지 않는다.** 화면의 실제 구현 여부는 각 기능 PR의 병합 상태와 앱의 `AREAS.ours`/page renderer·BETA 포트 연결을 확인해 판단합니다. PR #342/#353 및 이후 #361/#372/#410/#420/#422/#417 등의 코드는 이미 main에 병합됐지만, **합성 또는 미연결 BETA 화면을 학교 공식 시스템·운영 서비스 완료로 표시하지 않습니다.** [업무 배정 플레이북](ISSUE_ASSIGNMENT_PLAYBOOK.md) · [팀 운영](WORKSTREAMS.md).
