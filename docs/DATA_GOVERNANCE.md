# HUFS One AI — 승인된 데이터 처리와 사용자별 보호

## 현재 승인

소유자는 문서상 개인정보·자료·기관/출처·수집·보관·공유/게시·클라우드 및 AI 전송 승인을 모두 완료했다고 확인했습니다. **OWNER_CONFIRMED_APPROVED**를 사용하며, 승인된 실제 정보 사용을 일괄 차단하지 않습니다. 이 기록은 소유자 확인이며 별도 계약서나 독립 검증을 읽었다는 주장은 아닙니다. [정본](AUTHORIZATION.md).

## 정상 서비스 경계

실제 정보는 인증된 사용자·현재 소유권/역할·목적에 맞는 API/DB에서 처리합니다. 프로젝트의 승인 완료가 익명의 타인 조회·ADMIN 사칭·비밀키 공개를 허용하지는 않습니다. 계정 세션·CSRF·RLS·현재 삭제/철회·버전 충돌·원문 정확성 검사는 유지합니다.

| 자료 | 처리 기준 |
| --- | --- |
| 사용자 경험·프로필·학업 원장 | 소유자/동의 버전과 실제 자료 내용에 결속; 추정된 경험·학점·성적을 생성하지 않음 |
| 학교·기관 원문/포스터/PDF | 승인된 사용 범위에서 SourceRevision·SHA·시점/문단/bbox를 기록하며 수집 사실과 AI 해석 후보를 구별 |
| 클라우드/모델 입력 | 현재 사용자 및 실제 입력 범위를 유지하고 가격/토큰·취소/중복 정산과 결과 근거를 검증 |
| 세션/자격증명 | 서버 비밀 저장소에서만 사용; 이슈·CI·공개 번들에 키/토큰을 복사하지 않음 |
| 합성 자료 | 실제 사용자 원본과 다른 네임스페이스로 테스트; 실제 성과로 소개하지 않음 |

## 삭제·철회와 테스트

원문/경험 수정, 개인별 실제 철회, 세션 종료가 발생하면 파생 태그·캐시·추천·이미지 접근권이 함께 갱신되어야 합니다. 승인되었다는 이유로 이후 삭제 요구나 권한 변경을 무시하지 않습니다.

Git/CI 검사는 자격증명·의도하지 않은 원본 포함을 잡는 품질 검사이며 실제 서비스 내 정보 사용 허가를 취소하는 절차가 아닙니다. 실제 원본이나 전체 Git 이력을 검사하지 않았다면 검사 완료라고 쓰지 않습니다. #252에는 실제 실행/검증 결과만 기록합니다.
