# HUFS One AI — 승인된 데이터 처리와 사용자별 보호

## 현재 승인

소유자는 문서상 개인정보·자료·기관/출처·수집·보관·공유/게시·클라우드 및 AI 전송 승인을 모두 완료했다고 확인했습니다. **OWNER_CONFIRMED_APPROVED**를 사용하며, 승인된 실제 정보 사용을 일괄 차단하지 않습니다. 이 기록은 소유자 확인이며 별도 계약서나 독립 검증을 읽었다는 주장은 아닙니다. [정본](AUTHORIZATION.md).

## 공개 웹 데이터 수집 기본 정책 (2026-11-10 제안)

**공개정보를 먼저 발견하고, 이용 범위를 분리해서 검증한다.** 로그인 없는 공식 공개 페이지·공지·학칙·교과·장학·첨부파일 등은 도메인/사이트 단위 발견 대상으로 관리하며 각 URL별 수동 사전 허가가 없는 것만으로 수집 후보에서 제외하지 않는다. 정상적인 일반 학생 접근이 필요한 **공통 자료**도 별도 비공개·권한 범위에서 수집 후보로 관리하되 개인별 원장을 대량 수집/공개하는 정책과 혼동하지 않는다.

`robots.txt`의 자동 수집 지시는 준수해야 하는 사이트 규칙이며 접근권의 증명도 아니다. `Disallow`를 수집 후보의 **영구 삭제 사유**로 삼지는 않지만 허용되지 않은 자동 우회를 승인한다는 뜻도 아니다. 공식 RSS/API, 이용조건과 공개성에 관한 운영자 검토 기록, 정당한 브라우저 저장본, 제공자 허가 등 취득 경로를 추적한다. 공개 웹 접근과 **원문 사본 보관·전체 재게시·외부 모델 전송·개인정보 활용 허용**을 동일시하지 않는다.

실제 서비스에 연결할 때는 기존 `SourceRevision`·근거 SHA·판본·검증·철회/삭제 보호를 유지한다. **신규 수집기의 기술 구현은 별도 작업이며 현재 완료되지 않았다.** 정책 정본: [PUBLIC_WEB_INGESTION_POLICY](PUBLIC_WEB_INGESTION_POLICY.md).

## 추가 기능에서 데이터 요청·동시 담당 배정 (2026-11-08)

**김채윤 `qamarrchae`은 공식 실사용 자료·포스터/이미지·출처·이용권·변경판본·독립 Gold/웹 디자인 콘텐츠의 데이터 책임자**다. 새 `[추가 기능]`에 공식 문서·모집 규정·공고/행사·이미지·공개 통계·번역·OCR/RAG 자료·Gold가 필요하면 **별도 `[데이터 요청][김채윤]` 이슈**를 발행하고, 김채윤을 **추가 기능 이슈의 공동 assignee**에도 지정한다. 새 자료 요청의 주 assignee는 김채윤이며, 자료 목록·입출력 스키마·사용 권리·출처 revision·Gold/디자인 공급 이력을 그 자료 이슈에 남긴다. 고정 역할 `[본선 진출 이후]` #355–#359는 **완전 읽기 전용**으로 유지해 요청/진척 댓글도 추가하지 않는다.

**현재 대규모 데이터 요청:** [#360](https://github.com/ot4562-glitch/HUFS-One-AI/issues/360). 개발 중인 13개 기능 전체에 공식 원문·게시 허가 포스터·원문 근거 위치·독립 Gold·웹 콘텐츠를 요청했다. [PR #342](https://github.com/ot4562-glitch/HUFS-One-AI/pull/342)의 `ActivityRecord/ExchangePolicy/FaqDocument`, [PR #353](https://github.com/ot4562-glitch/HUFS-One-AI/pull/353)의 `FeatureSource`·장학/멘토/상담/증빙/NCS/검색/배지/학습/통계/국제학생 타입을 자료 스키마 기준으로 확인한다. 합성 픽스처를 실제 학교 정본으로 바꾸지 않는다.

- **추진 순서:** 심민성이 신규 기능의 일반 코드·계약/DB/API·통합을 가능한 만큼 먼저 구현한다. **규칙/추천/랭킹 등 코드 기반 AI를 포함한 AI 기능**은 이의상 또는 박준영에게 개발을 인계한다. 박준영은 기술 AI QA, 이의상·박준영은 상호 리뷰, 김채윤은 데이터를 넣으며 가볍게 사용자 시연, 이서연은 실제 웹 디자인·배치를 진행한다.
- **권리 원장:** 자료별로 공식 URL/기관·발행시각/검증시각·`sourceId/revisionId/evidenceSpanIds/rights/effectiveFrom/Until`과 **메타데이터·웹 포스터 게시·OCR 전송·HCX-007 사용·독립 평가**를 목적별로 기록한다. 웹 이미지 자산과 모델/평가용 원문은 목적·게시권에 따라 인수 경로를 구분한다.
- **규모:** 실제 공고 수·이미지 게시 허가 건수·Gold 정답 건수는 미확정이다. 원문/권리 확보율·검수 시간·정정량·UI/AI 필요량으로 단계별 합의한다. 완료와 미측정은 근거별로 구분한다.
- **개인자료:** 공개 이슈에는 원본 학생 명단/성적·실명/SID·비공개 영수증·계정/토큰을 첨부하지 않는다. 제품의 기존 `csv/` 5개 원본은 아래 보존 규칙 그대로 유지한다.

## 정상 서비스 경계

실제 정보는 인증된 사용자·현재 소유권/역할·목적에 맞는 API/DB에서 처리합니다. 프로젝트의 승인 완료가 익명의 타인 조회·ADMIN 사칭·비밀키 공개를 허용하지는 않습니다. 계정 세션·CSRF·RLS·현재 삭제/철회·버전 충돌·원문 정확성 검사는 유지합니다.

**2026-11-12 현행 상태:** [#362](https://github.com/ot4562-glitch/HUFS-One-AI/issues/362)는 2026-11-09 코드/감사 단계 `CLOSED/completed`로 기록됐지만, **실제 원본 게시·재게시 동의 또는 기존 공개 Git 복제본의 권리가 확인됐다는 증거가 아닙니다**. 실자료 권리·검수·독립 Gold는 열린 [#360](https://github.com/ot4562-glitch/HUFS-One-AI/issues/360)/[#446](https://github.com/ot4562-glitch/HUFS-One-AI/issues/446)과 비공개 NCP 검수 원장으로 관리합니다. 저장소에 있는 원본 5개 파일과 역사·포크 접근 가능성을 검토해 제공자별 명시적 공개/재게시 동의·목적·재식별 위험을 비공개로 확인해야 합니다. 정규식 표면 검사나 소유자의 프로젝트 승인을 학생별 실제 게시권으로 간주하지 않습니다. 사람 검토·정보주체 요청 없이 과거 파일을 삭제/변경하거나 Git 기록을 강제 재작성하지 않습니다.

**2026-11-06 사용자 보존 예외:** 기존 `csv/`의 Forms 1개·수강 CSV 4개는 사용자가 공개 저장소에 복구한 상태를 그대로 보존합니다. 5개 원본은 **절대로 임의 삭제·수정·이동·이름 변경·재인코딩·Git 추적 해제하지 않습니다.** SHA 고정 검사가 예고 없이 일어나는 변경·제거를 차단합니다. 이는 공개 Git 이력으로 이미 접근 가능한 자료라는 보안 위험을 없애지 않으며, 학생별 현재 동의·원본 소유권·공개 목적 권한을 대신하지 않습니다. **추가 개인자료, 실명↔학번/SID 대응표, 키/토큰은 공개 Git·PR·CI·이슈에 올리지 않습니다.** 인증된 서비스의 API/DB는 현재 소유권·동의·목적에 맞는 최소 projection을 사용합니다. 이것은 프로젝트 전체 승인 대기에 따른 기능 차단이 아니라 운영 정보의 의도치 않은 공개를 방지하는 기본 경계입니다.

## 삭제·철회와 테스트

원문/경험 수정, 개인별 실제 철회, 세션 종료가 발생하면 파생 태그·캐시·추천·이미지 접근권이 함께 갱신되어야 합니다. 승인되었다는 이유로 이후 삭제 요구나 권한 변경을 무시하지 않습니다.

Git/CI 검사는 자격증명·의도하지 않은 원본 포함을 잡는 품질 검사이며 실제 서비스 내 정보 사용 허가를 취소하는 절차가 아닙니다. 실제 원본이나 전체 Git 이력을 검사하지 않았다면 검사 완료라고 쓰지 않습니다. #252에는 실제 실행/검증 결과만 기록합니다.
## CSV 원본 보존 및 실제 계정 연결

- GitHub `csv/`의 기존 5개는 **소스 원본(source of truth)** 이며, 오류 발견·마이그레이션·PR 병합·cleanup·재생성의 명목으로 **직접 수정·삭제 금지**. 스키마 변환이나 정제 결과는 새 비공개 DB/별도 파생 자료에 저장한다. 사용자 또는 정보주체가 명시적으로 수정·철회를 요청하면 원본 보존보다 현재 동의·삭제 의무가 우선한다.
- `tools/verify_release_boundary.py --committed-tree-only`는 CI에서 원본 내용 없이 **정확한 5개 파일의 경로·Git blob SHA**를 확인한다. 기존 5개의 의도치 않은 삭제·내용 변경, 다른 CSV 추가는 실패시킨다. CI sparse checkout과 빌드·공개 Pages 미리보기·Docker에는 원본을 넣지 않는다.
- 운영자 제한 레지스트리는 **검증된 인증 사용자 actor ID + Forms 행 원본 해시 + 해당 수강 CSV 해시 + 학생별 목적·동의**를 결속해야 한다. `tools/private_owner_registry.mjs attest`의 제한된 attestation은 임의의 `local-owner-*` 임시 ID가 아닌 **실제 검증된 BETA actorId/identityRef**를 입력받아야 한다. 파일명/표시이름/CSV 순서만으로 사용자를 추정하지 않는다.
- 기존 `/api/private-intake/self`는 인증된 BETA 본인 자료만 제공하고 조회 직전·직후 권리/원본을 다시 확인한다. 운영 구성 `createPostgresApplication({ownerIntake:{loadRegistry,verifyStorage,loadSources},...})`의 **서버 전용 제한 로더를 주입**해야 한다. 운영자 원장과 자격증명이 없으면 403/503으로 닫힌 상태를 유지하며 합성 계정으로 대체하지 않는다.
- `/api/private-intake/self`의 **대상 학생 자료 읽기**와 `api_intake_revisions`의 **검토·이력 DB 적재**는 별도다. DB에 CSV만 넣어서는 세션·소유권·UI가 바뀌지 않는다. BETA 홈은 현재 사용자에게 검증된 본인 CSV preview만 표시하며, 타 메뉴의 가상 추천·학칙 계산은 실제 자료로 가장하지 않는다.
- 공개 저장소의 학생 자료 노출 문제는 별도 권한 검토 대상이다. 사용자의 프로젝트 승인과 각 학생의 외부 공개·전송·유효한 동의는 분리해서 확인한다. **자동 삭제를 하지 않는 보존 원칙은 개인정보 삭제/철회를 거부한다는 뜻이 아니다.**
