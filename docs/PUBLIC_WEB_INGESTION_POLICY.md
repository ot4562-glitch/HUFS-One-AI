# HUFS One AI — 공개 웹·학생 공통 자료 수집 정책 (2026-11-10 제안)

> **상태: POLICY PROPOSAL, PARTIALLY IMPLEMENTED.** 본 문서는 기존 정책을 완화하는 설계 기준이다. 이 문서를 추가했다고 네트워크 크롤러, 학교 인증, 공개 재게시권 또는 실서비스 연결이 구현·승인된 것은 아니다. 실제 권리와 품질 검증은 별도다.

## 1. 원칙: 먼저 발견하고, 수집·저장·공개·AI 이용은 분리한다

HUFS One AI는 학사 공지, 교과정보, 장학, 비교과, 취업, 교환학생, 규정, 행사 등의 **일반 접근 가능한 사실 정보**를 최대한 빠짐없이 발견·정규화하는 것을 기본 목표로 한다. 자료마다 개별 URL을 사전에 수동 등록해야만 **발견(discovery)** 가능한 기존 폐쇄형 방식은 범용 공개 웹 수집에 사용하지 않는다. 발견된 URL과 제목·게시일 같은 최소 공개 메타데이터는 검토 대기 원장에 남길 수 있다. 원문 가져오기·사본 보관·서비스 노출·외부 모델 전송은 각각 독립적으로 판단한다.

접근 가능성은 범위 판정의 출발점일 뿐, 저작물 재게시·AI 학습·개인정보 처리에 대한 자동 허가는 아니다. 공개 학생 이름·연락처 등 개인정보는 공개 페이지에 있어도 필터링하고 처리 목적과 적법성을 별도로 확인한다. 수집한 사실·추출 후보와 공식 확정 판단을 혼동하지 않는다.

## 2. 접근 범위 분류

| 수집 대상 | 범위 | 기본 취급 |
| --- | --- | --- |
| `PUBLIC_ANONYMOUS` | 로그인 없이 일반 브라우저에서 누구나 접근하는 학교/기관 게시물·공개 PDF·첨부파일 | **기본 발견·구조화 대상.** 도메인 단위 소스 레지스트리, 출처·시점·변경 감지. 안전한 자동 수집은 사이트별 정책·기술 조건을 충족할 때 실행 |
| `STUDENT_COMMON` | 정상적인 학생 계정으로 공통적으로 열람할 수 있는 안내·교과·일정 | 수집 후보에 포함하되 **정당하게 접근 권한을 가진 계정/공식 제공 경로**를 통해서만 취득. 로그인 세션·파일/재게시 권한·이용 주체와 범위를 기록. 일반 공개 검색/AI 입력은 별도 허용 범위만 |
| `USER_PERSONAL` | 개인의 학적·성적·상담·등록금·신청 상태·계정 페이지 | **대량 공개 수집 대상이 아니다.** 본인 요청 및 인증/동의·목적별 API/비공개 intake에만 접근 |
| `RESTRICTED_OTHER` | 직원·관리자·다른 학생 전용 자료, 비공개 API 또는 우회해야만 도달하는 정보 | 허가된 범위 밖 자동 수집·탐색 금지 |

다른 학생의 로그인/세션·쿠키를 공유하거나 신분을 가장하지 않는다. 공개 게시판에도 개인식별정보가 들어 있으면 최소 수집·가림·삭제/철회 처리를 적용한다.

## 3. robots.txt와 사이트 제한

`robots.txt`는 **자동 크롤러에 대한 사이트 운영자의 규칙**이며 웹 접근 권한을 부여하는 장치가 아니다(RFC 9309). 한편 RFC 준수 크롤러는 해석 가능한 `Allow/Disallow` 지시를 따라야 하므로 `robots.txt`를 무조건 무시하는 방식을 기본값으로 만들지 않는다. `robots.txt`가 없거나 불명확한 경우도 무조건 수집권을 부여하는 근거가 되지 않는다.

- **자료의 발견/후보 등록은 robots Disallow만으로 영구 배제하지 않는다.** 해당 URL·접근 계층·원인·처리 방법을 원장에 남긴다.
- 자동 수집 가능할 때는 HTTP/RSS/sitemap/공식 데이터 제공을 먼저 사용하고 필요하면 허용된 범위에서 Playwright/Crawlee 브라우저 수집을 사용한다.
- `ROBOTS_DISALLOW`인 URL을 무조건 폐기하지 않는다. 기본은 운영자 검토 큐로 보내며, **비로그인 일반 공개 접근성·이용 조건·요청량 및 사용자 영향·관련 법령**을 확인하고 해당 출처의 검토 기록(`robotsReviewRef`)을 남긴 경우 HTTP 취득을 선택할 수 있다. 이 선택이 RFC 9309 준수를 뜻하지는 않으며, 사이트 규칙을 따르지 않는 것의 위험과 필요성을 운영자가 책임지고 판단한다. 검토가 어렵거나 실제 차단되는 경우 공식 API·제공자 허가·자료 요청·적법한 사용자 브라우저 저장본 등으로 취득 경로를 유지한다.
- 401/403, CAPTCHA, 차단 페이지, 속도 제한, 인증·권한 장벽은 단순한 robots 표시와 다르다. 우회 자동화, 가짜 학생 계정, 은닉 프록시/IP 회전으로 강행하지 않는다. 해당 소스는 `ACCESS_RESTRICTED`와 대체 취득 경로를 기록한다.
- 사이트별 요청량 상한, 백오프, `Retry-After`, 연락/중지 요청, 네트워크 비용을 준수한다. `Disallow` 자체를 법률상 금지 또는 무조건 허용과 동치로 해석하지 않는다.

**핵심 불변식:** *로봇 차단 때문에 수집 대상 원장이 지워지거나 자료가 존재하지 않는 것으로 취급되면 안 된다.* **반면 수집 방법이 제한되는 동안 실제 원문을 수집했다고 허위 기록해서도 안 된다.**

## 4. 단계별 수집·이용 결정

1. **발견**: 학교·공식 기관 사이트의 공개 URL, RSS, sitemap, 학교 페이지 내 링크를 발견하고 `sourceUrl`, 제목/분류, 발견 시점, 접근 등급과 처리 상태를 원장에 남긴다. SSRF/DNS/IP 차단과 안전한 URL 정규화는 유지한다.
2. **취득 방법 선정**: `HTTP`, `BROWSER`, `OFFICIAL_FEED`, `OPERATOR_SAVED`, `AUTHORIZED_STUDENT` 중 실제 허용된 방법을 기록한다. 자동 취득이 제한되면 `ACQUISITION_REVIEW`로 전환하고 허용 가능한 대체 방법을 찾는다.
3. **원문/첨부 보존**: 목적별 권리·계정 범위·보관 기간을 적용한다. 가능하다면 원본 SHA-256, ETag, 최신판 관계와 추출 위치를 기록한다. 대량 원문 재게시를 위한 사본 생성과 서비스 내부 사실 추출용 보관을 구분한다.
4. **구조화**: 원문과 분리된 공고 제목·지원 자격·대상 전공·기간·마감·공식 링크·규칙 범위를 추출한다. AI 후보는 `NEEDS_REVIEW`로 기록하고 근거 인용/문단·bbox를 연결한다.
5. **사용**: 내부 검색 및 맞춤 추천, 공공 웹 노출, 외부 LLM/OCR 전송, 원문 재게시를 별개의 사용 목적으로 관리한다. 적격·마감·졸업 판정은 기존 SourceRevision/RulePack 및 검증 절차를 따른다.
6. **정정·삭제**: 공지 정정/취소와 출처 변경, 학생/정보주체의 권리 철회, 게시 중지 요청은 파생 검색/AI 캐시까지 전파한다.

## 5. 기술 구현 백로그 (미구현 사항)

현재 `source-ingestion-durable.ts`는 **사전 정확 URL 등록/출처 권리 확인**만 허용하고 자동 발견/스케줄러가 없다. 이 정책 PR에서는 `permitted-curriculum.ts`의 **한정된 HTTP 교과자료 수집**에 `robots:'NOT_FOUND'`와 신뢰된 운영자 검토 기록(`robotsReviewRef`)을 요구하는 `robots:'DISALLOWED'` 경로를 추가했다. 이는 범용 크롤러나 무조건적 robots 무시가 아니다. `tools/collect_missing_references.py`는 참고문헌 일회성 수집기이며 `ROBOTS_DISALLOW`를 거부한다. **이 상태를 범용 자동 수집 완료로 주장하지 않는다.**

구현은 별도 PR/회귀 테스트로 진행한다.

- 공개 공식 도메인 기반 발견 큐 + URL/콘텐츠 중복 제거 + 증분 수집 + 오류와 누락 모니터링
- 출처별 로봇/약관/인가 신호와 취득 방법 원장 + `ROBOTS_DISALLOW`에서 수동/공식 제공 경로로 이관 가능한 작업 상태
- 비로그인 공개 자료와 학생 공통자료의 별도 수집 워커/스토리지·목적별 공개 경계
- PDF/HWP/HWPX·이미지 OCR 어댑터, 문단·표·원본 SHA 증거 연결
- `SourceRevision`, `SourceSpan`, `FeatureSource`에 신뢰 가능한 결과만 연결
- 로봇 제한/로그인/차단/공고 수정·삭제/개인정보 노출/권한 철회에 대한 자동·사람 회귀 평가

## 6. 실행·안전 경계

이 정책은 **프로젝트 소유자가 수집 확대 방향을 승인한 설계 결정**이며, 제3자 사이트가 특정 이용·재게시·개인정보 처리 목적을 허가했다는 사실을 만들어내지 않는다. 연구·개발/운영/대외 서비스 출시를 구분한다. `OWNER_CONFIRMED_APPROVED`, `CONFIGURATION_REQUIRED`, `HUMAN_ACCEPTED`, `RELEASE_BLOCKED` 상태의 기존 의미는 변경하지 않는다.
