## 범위와 시작

이 가이드는 #220으로 통합한 `/demo-profile`을 재현한다. 정확한 코드 검증 SHA·병합·CI와 남은 인수는 [STATUS](../STATUS.md)를 따른다. 네 가지 설정은 주전공, 취득 학점(미입력과 0 구분), 관심 분야 1–5개, 이중전공 상태다. 북마크·경험 초안·경험 신호·검색·수강계획·알림 선호는 같은 EMPTY_DEMO 버전으로 저장한다. 추천/공지/달력/동아리는 동일 응답의 고정 `asOf`와 원천 SHA-256을 소비한다. 공개 기회 40건·공지 10건·기존 독립 프로필 5개는 전부 합성이며, 미래 시점에 생성된 자료는 지금 목록에 표시하지 않는다.

Node 22.22.2 이상 22.x 또는 24.15.0 이상 24.x, 이미 설치한 의존성이 필요하다. 저장소 루트에서 터미널 두 개를 연다.

```sh
npm run start:api:synthetic-empty-demo
```

```sh
npm run dev:web -- --mode empty-demo
```

브라우저에서 `http://127.0.0.1:5173/api/dev/empty-demo/bootstrap`을 연다. 합성 세션이 생성되고 `/demo-profile`로 이동한다. 이 경로는 127.0.0.1에만 바인딩한 명시적 `--synthetic` 서버에서만 존재한다. `NODE_ENV=production` 또는 `HUFS_DEPLOY_ENV=production`이면 기동을 거부한다. 익명 API는 401, 비어 있는 실제 Owner 경로는 거부된다. 서버 재시작 시 메모리 데이터가 사라진다. 일반 제품의 `PostgresDemoProfileStore` 영속성은 아래의 별도 실제 PostgreSQL 테스트가 확인한다.

`?slot=B`는 다른 가상 actor의 격리 점검용이다. 같은 브라우저의 세션 쿠키가 바뀌므로 탭 복귀 시 권한을 재확인하고 이전 설정을 지운다. 서로 독립적인 두 소유자를 동시에 확인할 때는 별도 브라우저 프로필/시크릿 창을 사용한다. S01–S05, REVIEWER, 실제 자료 4인의 계정·등록부와 연결하지 않는다.

## 10분 발표와 5분 질문

1. **0–1분 — 경계:** 합성 데이터 배지와 별도 빈 계정을 보여 준다. 본인 인증된 실제 계정, 학교 공식 판정, 운영 서비스라고 설명하지 않는다.
2. **1–3분 — A→B:** 네 가지 설정을 채우고 저장한다. 추천 순위·관련도·자격 확인 상태·마감을 구분하고 B 설정으로 바꾼다. 학점은 0.5 단위이며 일부분만 채운 중간 설정은 저장할 수 없다.
3. **3–4분 — 상세:** 합성 원천/버전과 필수·우대·수료 조건을 읽고 비활성 실제 지원 버튼을 확인한다. 검색을 저장해 필터링하고, 검색어를 비워 다시 저장해 전체 목록으로 돌아간다.
4. **4–5분 — 경험:** 가상 경험을 저장하고 OFF 상태를 확인한다. 신호를 켠 뒤 관심과 경험의 관련도 계산을 비교한다. 삭제하거나 OFF로 돌릴 수 있다.
5. **5–6분 — 보관함·계획:** 북마크, `SYN-COURSE-001` 계획 초안, 알림 선호를 저장한다. 실제 신청·학점 인정·알림 발송이 아님을 확인한다.
6. **6–7분 — 달력·공지:** 2주 날짜 버튼을 키보드로 탐색하고 학생 마감/행사/날짜 미정/UNKNOWN을 읽는다. 행정 보고 마감은 개인 제출 마감에 합치지 않는다.
7. **7–8분 — 학업·동아리:** 졸업/개설 UNKNOWN과 NOT_SHARED를 확인한다. 가상 동아리 추천을 읽는다. 실제 승인권한이 있는 별도 `/clubs/admin` 시연은 해당 기능의 운영 가이드와 권한이 준비된 경우에만 진행한다.
8. **8–9분 — 복구:** 같은 계정의 두 탭을 연다. 한 탭에서 설정을 저장하거나 RESET하면 다른 탭도 현재 권한과 버전을 재조회한다. 탭 복귀 시 권한 확인 중에는 이전 내용을 표시하지 않는다.
9. **9–10분 — RESET/종료:** 초기화 확인에서 먼저 취소해 값 유지 확인, 다시 전체 초기화를 확정해 네 설정·경험·북마크·검색·계획·알림 선호가 함께 비워짐을 확인한다. 종료 동작도 서버 초기화 성공 후 화면을 비운다.
10. **질문 5분:** 실제 입력 출처/사용권, UNKNOWN의 이유, 고정 시각과 권한 만료 시각의 차이, 동시 저장 충돌, 실제 AI·로그인·운영 DB의 미검증 범위를 답한다. 점수는 관련도이며 합격 가능성이나 공식 자격 판정이 아니다.

## 실패·오프라인·REVIEWER 복구

- 인터넷/외부 AI/원문 허가가 없어도 설치된 의존성과 합성 서버만으로 위 경로를 시연한다. 외부 provider 호출·실학생 원문·학교 로그인을 활성화하지 않는다.
- 401/403/409/503, 세션 교체·만료 시 이전 응답과 입력 초안을 숨긴다. 새 합성 세션으로 다시 입장하고 현재 버전을 읽는다. 409 후 이전 expectedVersion을 자동 재시도해 덮어쓰지 않는다.
- 브라우저 BroadcastChannel은 데이터가 없는 무효화 신호만 전달한다. 채널을 지원하지 않으면 탭 복귀/재초점/새로고침 시 서버 재확인을 사용한다. localStorage에 계정 상태를 저장하지 않는다.
- 서버 재시작 후 합성 메모리 상태는 초기화된다. 실제 PostgreSQL에서는 새 어댑터 인스턴스로 저장값을 다시 읽는 별도 검증을 사용한다. 두 환경의 결과를 혼동하지 않는다.
- REVIEWER 입장/초대 발급/기간 만료는 [REVIEWER_ACCESS](REVIEWER_ACCESS.md)의 독립 경로다. REVIEWER로 EMPTY_DEMO 소유자 설정을 열거나 실제 4인 원본을 선택할 수 없다. 실제 메일 전송과 사람의 초대 수락을 자동 검증했다고 기록하지 않는다.
- 실제 AI가 없을 때 화면의 코드 기반 근거와 합성 결과를 설명한다. AI를 사용한 것처럼 보이는 임의 응답을 추가하지 않는다. 기회 표지 8종·빈 화면·ED 이니셜은 직접 제작한 SVG fallback이며 AI 생성물이 아니다.

관리자와 BETA는 같은 쿠키 이름을 쓴다. 같은 브라우저에서 bootstrap을 열면 역할이 바뀌고 전체 페이지를 다시 읽는다. 두 역할을 나란히 보려면 별도 브라우저 프로필/시크릿 창을 사용한다. 기존 탭은 복귀 시 세션을 재확인하며 이전 역할의 내용과 입력 초안을 숨긴다. 세션은 1시간이고 두 역할을 합쳐 최대 32개다. 만료 후 해당 bootstrap으로 재입장할 수 있으며, 로그아웃한 세션은 재사용할 수 없다. 새 ADMIN 경로는 role/actor query를 받지 않는다.

이 절의 **동아리 추천만** 서버가 A→S01, B→S02의 기존 합성 관심 fixture를 선택한다. 원래 S01–S05 자료를 사용자의 EMPTY_DEMO 원장으로 복사하거나 연결하지 않으며, `/demo-profile`의 네 설정 변경이 이 고정 동아리 fixture를 수정하지도 않는다. 학교 실제 자료 4인이나 REVIEWER 초대·권한과는 별개다. 추천의 `asOf`는 기존 합성 동아리 corpus의 고정 시각이고, 로그인·만료의 서버 시각과 구별한다.

포스터는 `packages/fixtures/synthetic/clubs/generated/manifest.json`의 등록된 asset이며, `ai-club-poster-v1.png`의 SHA-256은 `93446df5cc9a2859585e4801df7a74b7f602d71ae8084a4a51f5b563855af842`다. 공개 정적 디렉터리로 노출하지 않고 현재 승인된 글과 BETA 권한을 확인하는 API로만 제공한다. 이미지의 생성 출처는 manifest에 기록하며, 이번 시연 중 모델이 이미지를 생성하거나 유료 OCR을 실행했다고 설명하지 않는다.

이 로컬 실행은 `MemorySyntheticClubDemoStore`를 사용하므로 재시작하면 추가·수정·승인이 사라진다. 영속 PostgreSQL 경로와 실제 운영 권한은 별도로 검증한다. 관리자 게시와 소유자 읽기를 조립한 회귀는 다음과 같이 실행한다.

```sh
npm test -- tests/api/synthetic-club-dev-fixture.test.ts tests/api/empty-demo-fixture.test.ts --maxWorkers=1
```
