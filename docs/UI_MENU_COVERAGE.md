# HUFS One AI 메뉴 대응표 (#141 · #124)

이 문서는 기존 HUFSAbility 학생 메뉴가 HUFS One AI 화면에서 **어떻게 보이는지**를 출처별로 적은 대응표입니다. 같은 디자인을 복제하라는 지시가 아니고, 원래 기능을 구현했다는 주장도 아닙니다. 독립 팀 프로젝트이며 학교 공식 서비스가 아닙니다.

- **정본:** HUFSAbility 원래 메뉴의 이름·순서·상태는 중앙 매니페스트 `packages/contracts/src/hufsability/manifest.ts`(`hufsability-public-2026-10-29-v1`)만 따릅니다. 웹 `apps/web/src/shell/menuCatalog.ts`는 이 매니페스트를 그대로 읽고, 원래 메뉴를 UI가 따로 "시연 가능"으로 바꾸지 않습니다.
- **관찰 자료:** 로그인 후 11개 영역·76개 화면 구조는 [UI 아틀라스](HUFSABILITY_UI_COMPONENT_ATLAS.md) §3·§7(2026-11-02 학생 계정 스냅샷)을 따릅니다. 원본 HTML·캡처·학교 자산은 쓰지 않습니다.

## 1. 공개 5분류 · 24기능 · 비로그인 4영역 (매니페스트)

| 출처 | 화면 표시 | 동작 |
|---|---|---|
| 5분류 24기능 (역량관리 4, 교과/비교과 5, 채용 6, 경력개발 4, 통합상담 5) | 공식 명칭·순서 그대로, `🚫 미지원` | 링크·버튼 없음, 포커스 안 됨, 스크린리더에 "이번 시연 미지원" |
| 비로그인 4영역 (교내비교과, 장학공지, 공지사항, 채용정보) | `🚫 시연 불가` + ↗ | 학교 공식 HUFSAbility 첫 화면으로만 이동(새 창, `noopener noreferrer`). 개별 서비스 연결은 검증 전 |
| HUFS One AI 확장 8개 (오늘, 맞춤 기회, 학사 공지, 졸업지원, 나의 경험, 보관함, 지원 현황, 동아리 모집) | 별도 묶음 "HUFS One AI 확장" | 합성 데이터 시연 화면. 원래 메뉴 이름을 빌려 쓰지 않음 |

매니페스트가 어떤 원래 기능을 `DEMO_AVAILABLE` + 검토된 경로로 바꾸면, 그 항목만 앱 안 화면으로 열립니다. 이 판단은 UI 코드가 아닌 매니페스트 검토(통합 담당)에서 정합니다.

"관련 독립 화면"은 같은 목적을 HUFS One AI 방식으로 다루는 **별도 기능**입니다. 원래 화면의 신청·조회·제출 기능을 대신하지 않습니다.

**남은 차이:** 4·7~11번 6개 영역은 공개 24기능 매니페스트에 없어 메뉴에 보이지 않습니다. 정보구조에 남기려면 매니페스트에 `UNVERIFIED`(🚫 검증 전) 관찰 영역을 추가하는 계약 변경이 필요합니다. 현재 스키마는 정확히 5분류·24개만 허용하므로, UI가 임의로 추가하지 않고 통합 담당(심민성)에게 요청합니다(#141 댓글).

## 3. 화면 확인 기준

- 360px: 사이드바 대신 `/menu` 전체 메뉴 페이지를 씁니다. 가로 스크롤이 없어야 합니다.
- 키보드: 앱 안 화면과 공식 홈페이지 링크만 Tab 순서에 들어가고, 🚫 미지원 항목은 건너뜁니다.
- 상태는 색이 아닌 🚫 아이콘과 글자로 표시합니다.
- 회귀 테스트: `apps/web/src/shell/menu.test.tsx` — 매니페스트와 id·이름·상태 일치, 원래 메뉴 링크 0개, 공개 4영역 외부 링크 속성. `apps/web/e2e/ui.spec.ts` — 360px 가로 넘침·Tab 순서.
