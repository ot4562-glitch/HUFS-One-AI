**2026-11-03 조사본 · 목적: ‘코드를 많이 만들었다’가 아니라 ‘실제 사용 가능한 서비스를 안전하게 완성하고, NCP에서 복원 가능하게 운영한다’.** 비용/실학생·학교 자료/외부 AI/배포는 사용자 사전 승인 전 실행 금지. 현 상태의 최종 운영 승인 여부는 [STATUS](../STATUS.md)·[#46](https://github.com/ot4562-glitch/HUFS-One-AI/issues/46)·[#89](https://github.com/ot4562-glitch/HUFS-One-AI/issues/89)로 판단한다.

## 왜 50%대가 오래 지속되는가?

[TEAM_PROGRESS](TEAM_PROGRESS.md) 숫자는 소프트웨어·제품 완성도 점수가 아니라 **담당자별 고정 ‘복합 수락 게이트’ 통과 수 / 분모**이다. 일부라도 미완료면 0점이어서 PR·코드·테스트가 추가되어도 증가하지 않는다.

| 담당/지표 | 현재 고정 수락 | 다음 수락으로 점수 오를 때 필요한 실제 증거 |

**원인 ①:** 완료까지 몇 가지 외부 증거가 모두 필요한 큰 게이트만 남았고, 단계별 부분 진척률을 표시하지 않는다. **원인 ②:** 합성/오프라인 코드 CI와 **실 Google·PG·공식 자료 권리·NCP 유료 서비스/실호스트**가 다르다. **원인 ③:** 보안·provider·런타임·배포 코드가 심민성에게 집중돼 #150 큰 통합 PR이 선행 #145/#148/#131과 충돌해 정체되어 있다. **원인 ④:** [#46](https://github.com/ot4562-glitch/HUFS-One-AI/issues/46) 2 FAIL, 인적 평가 [#61](https://github.com/ot4562-glitch/HUFS-One-AI/issues/61) **0/200**, 원본 이용권·학교 이메일 등의 **외부 의사결정**을 PR 수 증가로 대체할 수 없다. [#89](https://github.com/ot4562-glitch/HUFS-One-AI/issues/89)는 현재 RELEASE_BLOCKED.

**결론:** 50%대는 업무량·코드/기능 완성률이 아니며, 진척이 없다는 뜻도 아니다. 반대로 50%가 이미 운영 가능한 상태라는 뜻도 아니다. 고정 게이트 숫자는 보존하되 별도 **기능 코드 / 통합 / 검증 / 클라우드 운영** 4축을 반드시 표시한다. 아직 4축의 백분율 분모/실측은 없으므로 임의의 새로운 제품 완성도를 80%나 95%로 단정하지 않는다.

## 현실적인 예상 기간 — 약속이나 측정된 속도가 아닌 조건부 시나리오

**기준일 2026-11-03, 5인 역할이 병렬로 협업·PR 최신 HEAD 리뷰/CI 수행하며 유료 자원 승인과 학교 권리 답변은 아직 없다는 가정.** 일 단위 개발자 작업량/리뷰 지연/기관 승인 소요가 따로 측정돼 있지 않아 과거 PR 수만으로 정밀한 완료일을 계산할 수 없다.

| 목표 | 조건이 충족되는 경우의 대략적 범위 | 범위를 가장 늘리는 의존 |

| **합성 시연·NCP SSH 전용 미리보기** | **약 1–2주**(5–10 작업일) | #134의 미병합 고유 기능 재선별 및 #150 충돌·현재 UI PR들을 안전하게 재검증, 합성 UI 통합, Ubuntu/공인IP 실제 권한·허가, SSH/Node 환경 |
